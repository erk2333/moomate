# 派对破冰与玩伴匹配产品需求

> 用途：作为 Codex 开发派对现场破冰、人物标签和组队匹配功能的产品说明。  
> 产品场景：线下派对现场；参与者通过轻量问答快速了解彼此并组成玩伴小组。

## 1. 产品目标

帮助派对参与者快速找到今晚想做的事相近、互动方式合拍的玩伴。问答应轻松、可跳过；标签描述的是参与者**当晚的偏好**，不用于判断固定人格。

## 2. 破冰问卷

共 10 题。单选题必须选 1 项；多选题按题目限制选择。兴趣题可提供“其他”文本补充。问卷答案用于展示标签和匹配，不收集敏感人格判断。

| # | 问题 | 题型 | 选项 |
|---|---|---|---|
| 1 | 聚会时，你通常是哪一型？ | 单选 | 组织者 / 气氛组 / 自在参与 / 先观察 |
| 2 | 玩游戏，你更喜欢？ | 单选 | 合作通关 / 轻松体验 / 认真争胜 |
| 3 | 怎样互动让你最自在？ | 多选，最多 2 项 | 喜欢别人主动破冰 / 慢慢熟悉 / 一起做点事 / 不被突然点名 / 可以互开玩笑 |
| 4 | 什么样的人最合你玩？ | 多选，最多 2 项 | 会聊天 / 有行动力 / 松弛随和 / 兴趣相投 |
| 5 | 今晚最想做什么？ | 多选，最多 2 项 | 交朋友 / 放松 / 玩游戏 / 跳舞 / 找活动搭子 |
| 6 | 你更喜欢哪种聚会？ | 单选 | 热闹大场子 / 几个人深入聊 / 都可以 |
| 7 | 认识新朋友时，你通常会？ | 单选 | 主动开聊 / 等别人搭话 / 看气氛 |
| 8 | 最近什么让你特别上头？ | 多选 | 音乐 / 运动 / 旅行 / 游戏 / 影视 / 美食 / 其他（可填写） |
| 9 | 遇到没试过的活动，你会？ | 单选 | 马上参加 / 先了解一下 / 更喜欢熟悉的活动 |
| 10 | 派对结束后，你想？ | 单选 | 吃宵夜 / 散步聊天 / 再玩一局 / 回家休息 / 看情况 |

问卷可逐题填写或一次展示；应明确标出单选、多选及最多选择数。允许跳过非必答题，并在匹配时将缺失答案视为中性，不推断答案。

## 3. 人物标签

每位参与者生成 **3–5 个标签**。标签应优先反映当晚社交方式、活动意愿和兴趣，避免把偏好的玩伴类型误写成参与者本人的性格。

### 标签类别与映射

| 类别 | 答案映射示例 |
|---|---|
| 社交风格（题 1、7） | 组织者、气氛担当、自在参与、先观察、主动破冰、慢热型、看氛围 |
| 互动偏好（题 3） | 喜欢主动交流、喜欢边玩边熟、不爱被点名、玩笑友好型 |
| 游戏风格（题 2） | 合作派、轻松体验派、竞技派 |
| 今晚目的（题 5、6） | 交友优先、放松为主、游戏优先、舞池活跃、小圈聊天、热闹大场 |
| 兴趣与尝新（题 8、9） | 音乐控、运动爱好者、旅行爱好者、游戏爱好者、影视爱好者、美食爱好者、爱尝鲜、先了解再参加 |
| 玩伴期待（题 4） | 想找会聊天的搭子、想找行动派搭子、想找轻松随和的搭子、想找同好 |
| 续摊偏好（题 10） | 宵夜续摊派、散步聊天派、再玩一局派、适时回家派 |

### 标签挑选规则

1. 优先选择有明确答案支持的标签；不为补足数量而编造标签。
2. 去除含义重复的标签，例如“先观察”和“慢热型”同时出现时保留更有区分度的一项。
3. 通常按以下顺序选取：社交风格 1 个、互动或游戏偏好 1 个、今晚目的 1 个，再从兴趣、玩伴期待、续摊偏好中补充 0–2 个。
4. 多选兴趣最多展示 2 个代表性标签；其余兴趣可放在个人详情中。
5. 示例：`气氛担当 · 合作派 · 今晚想交友 · 音乐控 · 宵夜续摊派`。

## 4. 匹配人数设置

- 每位参与者设置今晚期望加入的小组人数，范围 **2–20 人**。人数含本人。
- 默认按所选人数精确组队。产品可额外提供“人数不足时接受小组少 1–2 人”的可选开关；未经同意不得改变用户选择的人数。
- 参与者可选择暂不匹配或退出等待。退出后不再进入后续组队。
- 对人数不足的等待池，显示等待状态；可邀请用户调整人数或开启人数浮动，不自动降低人数要求。

## 5. 匹配评分

以参与者原始答案计算两两匹配分 `pairScore`，范围 0–100。标签用于说明匹配理由；评分优先使用问卷答案，避免标签压缩造成信息丢失。

| 匹配维度 | 权重 | 评分方式 |
|---|---:|---|
| 今晚目的（题 5） | 25 | 共同选择越多越高；按所选项的 Jaccard 相似度计分。 |
| 兴趣（题 8） | 20 | 共同兴趣越多越高；按 Jaccard 相似度计分。 |
| 活动偏好（题 2、9） | 15 | 先分别计算两题兼容度，再取平均。相同偏好高；轻松体验与合作较兼容；竞技与轻松体验较低。尝新意愿相同或相近时较高。 |
| 社交风格与互动（题 1、3、7） | 15 | 评估是否易于一起开启互动。主动者与等待破冰者可适度互补；“看气氛”保持中性。互动偏好明显冲突时降低分数。 |
| 小组规模偏好（题 6） | 10 | 按实际目标人数评估：2–5 人视为小组，8–20 人视为大组；“都可以”记中性。6–7 人处于中间，分数线性过渡。 |
| 玩伴期待（题 4） | 10 | 双向计算：一方期待的特征是否能在另一方答案中找到，再取双向平均。兴趣相投依据共同兴趣；行动力可参考组织者、气氛组或主动开聊；轻松随和参考休闲体验偏好。 |
| 续摊偏好（题 10） | 5 | 相同或相容的续摊选项较高；“看情况”视为中性。 |

各维度先归一化到 0–100，再按权重加权求和。多选集合使用 `Jaccard(A,B)=|A∩B|/|A∪B|`；若任一方未回答该题，该维度记 50 分（中性）。维度内部的兼容度映射表应集中配置，便于后续调整。

### 互动边界

- 题 3 的“不被突然点名”是活动安排约束：匹配后不应向该参与者强制安排个人展示或当众自我介绍。
- 匹配分不能覆盖明确边界；如活动需要点名或公开表达，应选择其他活动或事先征求同意。
- 不因慢热、兴趣少或未填写答案直接淘汰参与者。

## 6. 组队算法

### 输入

当晚仍在等待且同意参与匹配的玩家、问卷答案、目标组人数，以及可选的人数浮动许可。

### 组队步骤

1. **分池**：按目标人数和人数浮动许可划分候选池。仅将人数规则相容的玩家放入同一候选池。
2. **确定主题**：从今晚目的、共同兴趣和活动偏好中，优先为小组确定一个共同活动锚点，例如桌游、聊天、跳舞或宵夜。
3. **选择种子玩家**：在候选池中选取 pairScore 最高且有共同活动锚点的一对作为起始组。若最高分并列，使用稳定随机顺序打破平局。
4. **逐人加入**：为当前小组计算每位候选人的加入分：该候选人与组内成员的 pairScore 平均值。优先加入平均分最高且符合人数规则、互动边界和共同活动锚点的人。
5. **成组检查**：小组人数达到目标后，计算组内所有 pairScore 的平均值。平均分达到 60 分且不存在边界冲突时，确认组队；否则尝试替换最后加入的成员。无法达标则不强行成组，候选人回到等待池。
6. **继续匹配**：从剩余玩家重复以上步骤，直到无法组成更多合格小组。
7. **通知结果**：展示小组人数、共同活动锚点及 1–3 条可解释的匹配理由，例如“你们都想认识新朋友，且都喜欢音乐”。

### 大组组织

目标人数为 11–20 人时，先组成满足人数和兼容度规则的大组，再提供 3–5 人的临时互动小队或轮换活动，降低大组中难以开口的问题。临时小队不改变主匹配组成员关系。

### 无法匹配时

- 人数不足：继续等待，并展示当前人数；提供修改目标人数或允许人数浮动的入口。
- 兼容度不足：说明暂未找到合适小组，允许继续等待或调整活动/人数偏好。
- 不得静默放宽用户设置或将未同意浮动的人放入不同人数的小组。

## 7. 匹配结果与可解释性

结果至少展示：

- 小组人数和共同活动主题；
- 参与者自己的 3–5 个标签；
- 1–3 条基于实际答案生成的匹配理由；
- 适合小组的破冰建议或下一步活动。

匹配理由必须能追溯到真实答案，不展示内部评分细节，不使用“性格不合”“不受欢迎”等评判性文案。

## 8. 验收标准

- 问卷完整呈现 10 个问题、题型和选项限制。
- 每位完成问卷的参与者生成 3–5 个有答案依据且无明显重复的标签。
- 目标人数可设为 2–20 人，组队人数遵守用户设置和浮动许可。
- 匹配结果可给出共同活动主题和可解释理由。
- 明确互动边界在组队及活动建议中得到遵守。
- 人数或兼容度不足时进入等待/调整流程，不强行组队。

## 9. 实现提示

当前项目为 Next.js + TypeScript + Supabase。实现时先检查现有参与者资料、房间状态和匹配流程，尽量扩展现有数据结构与匹配入口；问卷、标签生成和评分规则保持为可维护的独立逻辑，避免把匹配评分交给生成式 AI 决定。匹配应由服务端执行并保存结果，AI（若启用）仅用于润色匹配理由或破冰建议，且文案必须基于已保存的答案与匹配依据。
